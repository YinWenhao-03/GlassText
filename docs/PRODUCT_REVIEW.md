# 从产品经理与用户视角进行的迭代

目标不是堆积功能，而是让用户完成“放入资料 → 看清楚 → 锁定 → 找回控制”。这份记录来自代码走查、自动检查和界面预览，不冒充真实用户研究。

| 使用问题 | 本次处理 | 验证范围 |
|---|---|---|
| 参数一屏堆满，用户不知道先点什么 | Mac 分为内容/外观/提词；常用操作固定底部，高级设置收起 | AppKit 构建和界面预览 |
| 新手说明抽象，找不到控件 | 四步截图、红框编号和具体操作说明；可随时退出 | 截图生成与红框位置检查 |
| 锁定后不理解哪些操作可用 | 分开翻页/缩放锁定选项，Mac 显示允许/禁止状态 | 状态与操作回归 |
| PDF 放大后看不到边缘 | 增加平移与一键重置到适合窗口 | 代码路径检查；复杂 PDF 实机体验待验收 |
| 鼠标穿透后“找不回”应用 | 菜单栏/托盘恢复入口、全局快捷键、控制面板恢复按钮 | 状态检查；跨应用按键仍待实测 |
| 关闭面板误以为退出 | 文档明确关闭与退出区别，保留托盘/菜单栏入口 | 生命周期走查 |
| Word 支持容易产生误解 | 明确纯文字与保留版式差异，列出两端支持范围 | 中文 DOCX 样例与 Mac LibreOffice 转换 |
| 读取失败丢失当前资料 | 失败保持原内容，取消请求丢弃过期结果 | 错误/取消检查 |
| 跨平台宣传容易过度承诺 | 功能矩阵公开 Windows 尚未同步的能力和实机验证状态 | 文档核对 |

## 仍需继续迭代

1. Windows 真机端到端验收：透明、拖动、锁定、PDF 大文档、托盘恢复及多屏。
2. Windows PDF 去白开关、提词、阅读进度记忆和 DOC 支持。
3. 大文档导入/分页更细的进度反馈，Windows 任务取消目前是丢弃结果，不保证立即停止解析计算。
4. 任意快捷键录制、自动更新、多独立文档窗口。
5. 正式签名、公证、辅助技术可访问性和长期稳定性测试。
